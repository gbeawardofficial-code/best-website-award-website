# Winner resources

`/claim` is a static, non-indexable resource page with analytics disabled. It checks the submitted domain through the same-origin, rate-limited `/api/claim/lookup` endpoint. It does not take payments or send emails.

The live source of approval is `bwa.winner_resources`, separate from nomination and participation payments. The current operator-approved cohort is the 20 websites in `src/data/winners-2026.json`. Domain matching uses the existing `/accept` normalisation: HTTP/HTTPS, `www.`, page paths and tracking parameters do not change the website. Other subdomains and lookalike domains remain distinct.

`developer_name` is optional. Only Ceylon Envoy (Augmara) and Monarch Jewellers (DEGITALDEVS) have developer options. Their business and developer exports are separate. The developer badge adds the label `Developer` above the award title and includes the approved agency name. Other winners receive only business badges.

## Data updates

The following command applies only migration 006 and upserts the approved 20 records in one transaction, then compares every saved URL, title and developer name with the source. It does not modify nomination or payment records and never runs during builds or HTTP requests:

```sh
npm run winners:seed
```

Keep `DATABASE_URL` in the existing server environment. No new service credentials are required. Use the operator-approved source for any future change. The claim endpoint requires both active database approval and matching exported artwork; a changed title or developer name without corresponding exports fails closed rather than issuing an incorrect badge.

## Artwork

The approved A (Signature crest) and C (Architectural plaque) frames, in light and dark, are stored under `scripts/assets/winner-badges/`. These are the selected native-generated frames, with cleaned transparency. The original faceted blue logo is preserved; the reversed logo changes only the original black lettering to ivory. Text is composed using the existing Funnel Sans font. No award title, website or developer name is generated by AI.

Run `npm run assets:winners` after an approved content/artwork change. It uses local Playwright and Sharp only for manual export, never at runtime. It checks exact titles and text overflow, creates all 88 badge variants across 22 recipient sets, and writes three sizes in PNG and WebP (528 files) plus the typed asset manifest. PNG uses a 256-colour indexed palette; WebP uses quality 96 with full alpha. Each version has a fingerprinted static asset path, so files can use immutable CDN caching.

Sizes: crest 240, 480 and 980 pixels wide; plaque 600, 1200 and 1902 pixels wide. Dimensions in the download dialog come from the export manifest. Previews load lazily, and the selected original file downloads directly from the CDN. No browser resizing or server image rendering is involved.

The typed content adapter in `src/lib/content/claim.ts` supplies page content and approved asset metadata. Programme previews use `ManagedPicture.astro`. No winner listing, voting, new pricing or public programme claims were added elsewhere.

## Release checks

Run `npm run verify` and `npm run test:e2e`. The claim tests cover exact approval, optional developer scope, stale artwork rejection, domain spoofing, unavailable storage versus non-winner results, download formats and sizes, keyboard dismissal and focus restoration, desktop/mobile layout and real static file downloads. `/claim` is omitted from both sitemaps; claim API responses are `no-store`; resource files are non-indexable.
